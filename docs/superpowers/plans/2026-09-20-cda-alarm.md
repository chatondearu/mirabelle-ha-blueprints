# CDA Alarm v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Mirabelle `cda_alarm` Home Assistant integration that replaces Alarmo as the single alarm source of truth, with Frient keypad as input-only, unified codes, and blueprint retargeting including speaker/TTS noise in Alarm Response.

**Architecture:** New HACS-style package `packages/cda-alarm/` exposes one `alarm_control_panel` entity. Codes and sensors live in the config entry. Frient ZHA events arm/disarm that panel only (no mirror to the Frient ZHA panel). Existing blueprints keep standard `alarm_control_panel.*` services and read `open_sensors`. Media noise stays in `alarm-response`, not in the panel state machine.

**Tech Stack:** Home Assistant custom component (Python), `pytest-homeassistant-custom-component`, HA blueprint YAML, `nix develop -c` / `scripts/run_tests.sh`.

**Spec:** `docs/superpowers/specs/2026-09-20-cda-alarm-design.md`

**Out of this plan (follow-up plans):** v1.5 leave-home prompt, v2 house settling, v3 cover/light profiles, HACS sub-repo sync workflow.

## Global Constraints

- Target Home Assistant **2025.5.3** or later.
- Blueprint names start with **`[CDA]`**; repo docs and user-facing English.
- Domain / package id: **`cda_alarm`** (folder `packages/cda-alarm/`, Python package `custom_components/cda_alarm/`).
- Default entity id target for docs/blueprints: `alarm_control_panel.cda_alarm`.
- Open sensors on arm: **hard-block** by default (`block_arm_if_open: true` in options).
- Codes stored in **config entry data/options** (HA storage); never commit real PINs.
- Conventional Commits with required scope (e.g. `feat(cda-alarm): …`, `docs(cda-alarm): …`).
- Prefer `nix develop -c …` for project commands when using the flake shell.
- Do not push unless explicitly requested.

```python
"""Code matching for CDA Alarm."""

from __future__ import annotations

from typing import Any


def match_code(
    codes: list[dict[str, Any]],
    *,
    pin: str | None = None,
    rfid: str | None = None,
    nfc_tag_id: str | None = None,
) -> dict[str, Any] | None:
    """Return the first code entry matching pin, RFID, or NFC tag id."""
    pin_n = (pin or "").strip()
    rfid_n = (rfid or "").strip().lower()
    nfc_n = (nfc_tag_id or "").strip()
    for entry in codes:
        if pin_n and str(entry.get("pin") or "") == pin_n:
            return entry
        if rfid_n and str(entry.get("rfid") or "").strip().lower() == rfid_n:
            return entry
        if nfc_n and str(entry.get("nfc_tag_id") or "") == nfc_n:
            return entry
    return None
```

```python
    STATE_ALARM_TRIGGERED,

from homeassistant.helpers import entity_registry as er
from pytest_homeassistant_custom_component.common import MockConfigEntry

from custom_components.cda_alarm.const import DOMAIN


async def _setup_panel(hass: HomeAssistant, **overrides) -> str:
    data = {
        "name": "CDA Alarm",
        "codes": [{"name": "alice", "pin": "1234"}],
        "sensors_away": ["binary_sensor.front_door"],
        "sensors_home": [],
        "sensors_night": [],

        "block_arm_if_open": True,

    assert await hass.config_entries.async_setup(entry.entry_id)
    await hass.async_block_till_done()
    registry = er.async_get(hass)
    entities = [
        e
        for e in er.async_entries_for_config_entry(registry, entry.entry_id)
        if e.domain == ALARM_DOMAIN
    ]
    assert len(entities) == 1
    return entities[0].entity_id


@pytest.mark.asyncio
async def test_arm_away_and_trigger(hass: HomeAssistant) -> None:

        ALARM_DOMAIN,
```
